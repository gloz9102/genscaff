# Workflow Rubric

Use this shared rubric on rendered evidence. Score each applicable dimension from 0 to 5 and cite the viewport, state, or action trace.

| Score | Meaning |
| --- | --- |
| 0 | Missing, broken, misleading, or blocks the task. |
| 1 | Present but materially incomplete or difficult to use. |
| 2 | Works with a significant clarity, continuity, or adaptation problem. |
| 3 | Meets the brief and primary task without a material defect. |
| 4 | Strong task fit, hierarchy, and recovery with only minor issues. |
| 5 | Exceptional and fully evidenced for this workflow; do not award for polish alone. |

## Dimensions

- Functional completeness: required information, controls, terminal result, and recovery work.
- Efficiency: the task avoids unsupported decisions, clicks, confirmations, and disabled states.
- Project fit: existing components, tokens, content model, and interaction conventions are preserved.
- Visual hierarchy: attention follows the user's next decision instead of generic decoration.
- Responsive and accessibility basics: the task remains reachable, legible, keyboard-operable, and unobscured.

Apply hard pass/fail checks before scoring. A high visual score never compensates for a broken requirement, fabricated claim, dead control, missing recovery, or `FABRICATED_FRICTION`. Revise only dimensions below 3, at most twice, and report remaining failures.
