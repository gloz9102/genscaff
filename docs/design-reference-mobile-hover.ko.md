# 디자인 원칙 보완과 모바일 및 hover 관찰

확인일: 2026-09-22

## 범위와 방법

[토스](https://toss.im/), [디스코드](https://discord.com/), [애플 한국 홈페이지](https://www.apple.com/kr/)를 인앱 브라우저에서 직접 확인했습니다. 홈페이지 일부와 대표 컨트롤을 표본으로 삼았으며 사이트 전체 감사 결과가 아닙니다.

모바일 구성은 390×844, 데스크톱 hover는 1280×900에서 관찰했습니다. 모바일 검사에서도 `hover: hover`, `pointer: coarse`는 false인 데스크톱 입력 환경이었습니다. 따라서 반응형 구성과 클릭 경로를 확인한 것이며 실제 iOS/Android 터치, 길게 누르기, 모바일 앱 연결을 검증하지 않았습니다. 디스코드의 Windows 다운로드 표시는 이 실행 환경의 결과입니다.

접근성 트리와 스크린샷으로 상태를 관찰하고 DOM의 계산된 스타일로 대표 컨트롤의 색상과 transform을 확인했습니다. 도구에 독립적인 포인터 이동 명령이 없어 비활성 영역에서 대상까지 드래그한 후 버튼을 놓고 `:hover` 상태를 확인했습니다. 이 과정에서 텍스트 선택이 발생하기도 했으므로 선택 강조는 사이트의 hover 효과로 해석하지 않았습니다. 클릭 없이 진입한 최종 hover 상태를 확인했지만 순수 mousemove만으로 진행한 실험과 동일한 조건은 아닙니다.

## 모바일에서 관찰한 동작

| 사이트 | 구성 | 직접 확인한 메뉴 동작 | 적용할 원칙 |
|---|---|---|---|
| 토스 | 생활 장면을 세로 화면에 맞게 크롭하고 제목을 여러 줄로 배치합니다. 상단 내비게이션은 메뉴 버튼으로 바뀝니다. | 전체 메뉴 열기, 서비스 항목 펼치기, 메뉴 닫기를 확인했습니다. 하위 링크는 주제별 두 열로 배치됩니다. | 미디어 크롭과 문장 재배치를 별도로 설계합니다. 데스크톱 메뉴를 단순 축소하지 않습니다. |
| 디스코드 | 제품 이미지가 제목 위로 이동하며 설명과 주요 버튼이 세로로 이어집니다. | 메뉴 열기, 찾기 항목 펼치기, Close menu로 닫기를 확인했습니다. | 작은 화면에서는 콘텐츠 순서를 바꿀 수 있습니다. hover 없이도 하위 탐색에 접근할 수 있어야 합니다. |
| 애플 | 상단은 로고와 검색, 쇼핑백, 메뉴 중심으로 축약됩니다. 대표 제품의 탐색/구매 버튼은 나란히 유지됩니다. | 메뉴 열기, Mac 하위 단계 진입, 닫기를 확인했습니다. 하위 단계에는 뒤로 가기 모양의 컨트롤이 보였지만 해당 경로는 실행하지 않았습니다. | 모든 모바일 버튼을 일괄 세로 배치하지 않습니다. 내용과 실제 가용 너비에 맞춥니다. |

메뉴가 열린 표본 상태의 문서 너비는 토스 390px, 디스코드 375px, 애플 390px로 측정되었습니다. 이는 해당 상태에서 390px 뷰포트를 넘지 않았다는 관찰이며 전체 페이지의 모든 스크롤 상태가 통과했다는 의미는 아닙니다.

초기 로드와 메뉴 전환 도중에 빈 영역 또는 흐린 문구가 잡혔습니다. 이후 로드된 화면과 메뉴 전개 상태를 다시 확인했습니다. 중간 프레임만으로 최종 디자인 결함이나 로딩 성능 수치를 판정하지 않았습니다.

## 데스크톱 hover 표본

| 컨트롤 | 기본 상태 | 포인터 진입 상태 | 해제 후 확인 |
|---|---|---|---|
| 토스 앱 다운로드 | 버튼 배경 `rgba(7, 25, 76, 0.05)`, 내부 글자 transform 없음 | 버튼 전체는 이동하지 않고 내부 글자에 수직 이동 transform이 적용됩니다. 두 벌의 라벨이 교대하는 표현을 확인했습니다. | 비활성 영역으로 이동/클릭 후 글자 transform이 다시 없어졌습니다. |
| 디스코드 로그인 | 흰 배경, 검정 글자 | 연한 회색 배경 `rgb(232, 233, 235)`으로 변합니다. 관찰한 컨트롤에는 확대나 그림자 변화가 없었습니다. | 포인터가 벗어나고 전환이 끝나면 흰 배경으로 복원되었습니다. CSS에 선언된 배경 전환 시간은 0.25초입니다. 실측 지연 시간은 아닙니다. |
| 애플 Mac mini 더 알아보기 | 파란 배경 `rgb(0, 113, 227)` | 배경이 `rgb(0, 118, 223)`으로 바뀝니다. 글자색은 흰색이며 transform은 없습니다. | 포인터를 벗어나게 한 뒤 원래 배경색으로 돌아왔습니다. |

토스 서비스 항목에서는 포인터 진입 뒤 주제별 링크를 포함한 큰 메뉴가 나타났습니다. 메뉴가 나타나는 경로는 확인했지만 포인터 이탈만으로 닫히는 조건과 지연, 하위 영역 이동의 모든 경로는 확정하지 않았습니다. 이 메뉴의 닫힘 동작을 다른 제품의 규칙으로 채택하지 않습니다.

위 관찰은 hover가 반드시 확대, 튀어 오름, 그림자 추가여야 하는 것은 아니라는 판단을 뒷받침합니다. 단순 링크는 색상 변화로, 표현적인 CTA는 내부 요소의 움직임으로 반응할 수 있습니다. 이것은 세 사이트의 모든 컨트롤에 대한 일반화가 아닙니다.

## 스킬에 반영한 여섯 원칙

1. 섹션마다 핵심 메시지 또는 결정을 하나 정합니다. 비교에 필요한 관련 정보는 함께 제공하며 다음 섹션으로 이어지는 이유를 둡니다.
2. 여백으로 시선과 주제를 분리합니다. 빈 곳을 채우려고 내용을 만들지 않으며 필수 정보의 누락을 여백으로 정당화하지 않습니다.
3. 시각 자료가 주장을 설명하도록 제품, 사용 장면, 과정, 결과를 선택합니다. 가상의 콘셉트를 실증 자료처럼 제시하지 않습니다.
4. 즉각적인 컨트롤 반응과 콘텐츠 연출을 구분합니다. 스크롤 연출을 기다려야 버튼을 사용할 수 있는 구조를 피하고 정적 대체 경로를 둡니다.
5. 제품과 사용자에 맞춰 표현 강도를 조절합니다. 배경색 비율, 모서리 값 개수, 대형 제목 크기를 일률적인 탈락 기준으로 사용하지 않습니다.
6. 한국어 줄바꿈을 데스크톱과 모바일에서 직접 확인합니다. 주제 변경은 의미 구조로 분리하고 같은 문장 안에서는 자연스러운 단어와 구절을 유지합니다.

수정 위치는 [스킬 본문](../plugins/genscaff/skills/genscaff/SKILL.md), [UI 상세 지침](../plugins/genscaff/skills/genscaff/references/ui-craft-guidelines.md), [과도한 기본 패턴 검토](../plugins/genscaff/skills/genscaff/references/anti-slop.md), [검증 기준](../plugins/genscaff/skills/genscaff/references/verification-baseline.md)입니다.

## 검증과 남은 범위

`quick_validate.py`, `python tools/check_skill.py`, `python -B -m unittest discover -s tools -p test_plugin.py`, `git diff --check`를 실행했습니다. 스킬 구조 검증과 관련 테스트 8개가 통과했습니다.

실제 터치 기기, 사이트 전체 키보드 경로, hover 메뉴의 전체 진입/이탈 경로, 모바일 OS별 다운로드 라우팅, 세 사이트의 모션 감소 대응은 이번 관찰에서 검증하지 않았습니다. 스킬에 해당 검증 원칙을 추가한 사실과 참고 사이트가 이를 충족한다는 주장은 구분합니다. 스킬 변경의 생성 품질을 비교하는 A/B 평가도 실행하지 않았습니다.
